# Full UI i18n Coverage — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every user-visible string in `frontend/src` renders through react-i18next with complete `en`/`ms`/`zh-CN` translations; parity and no-hardcoded-strings enforced by tests.

**Architecture:** i18next singleton initialized in `src/i18n/` with bundled per-namespace JSON per locale, typed keys via `CustomTypeOptions`, browser detection + localStorage persistence, `LanguageSwitcher` in both shells + Login. Backend error strings map to keys inside `getErrorMessage`.

**Tech Stack:** React 19, react-i18next, i18next-browser-languagedetector, Vite 8, Vitest, TypeScript.

**Spec:** `docs/superpowers/specs/2026-09-15-i18n-coverage-design.md` (approved).

## Global Constraints

Every task implicitly includes:

- Locales: `en` (fallback/source of truth), `ms`, `zh-CN`. Every key added to `en` MUST be added to `ms` and `zh-CN` in the same commit — never leave a locale incomplete.
- Key style: `t('ns:path.to.key')`, camelCase segments. Interpolation `t('key', { var })`; plurals via `_one`/`_other` suffixes. Never concatenate translated fragments.
- Reuse `common:*` for identical global concepts (Save/Cancel/Delete/Loading/etc.). Feature-specific terms stay in the feature namespace.
- Components use `useTranslation('<ns>')`. Non-render code (catch blocks, interceptors, pure helpers) uses `import i18n from '@/i18n'` + `i18n.t(...)`.
- Do NOT translate: DB/user content (names, notes, file names), brand "PayrollMY", `RM` prefix, `en-GB` date format, `console.*`, third-party widget internals (Turnstile, html5-qrcode, WebAuthn dialogs). Browser/OS brand names (Chrome, Safari, Android…) stay literal; "Unknown OS/browser/device" DO translate.
- Validation per task, run from `frontend/`: `bun run typecheck && bun run lint && bun run test`. All must pass before commit.
- Commit style per repo history: `feat(i18n): <scope>` / `feat(i18n): cover <area>`.
- Translation register: professional Malaysian HR/payroll vocabulary. ms: Bahasa Melayu baku (e.g. "payslip"→"slip gaji", "attendance"→"kehadiran", "leave"→"cuti", "claim"→"tuntutan", "overtime"→"kerja lebih masa", "payroll"→"gaji"/"payroll" per context — prefer "penggajian" for the function, "gaji" for amounts). zh-CN: Simplified Chinese HR terms ("工资单", "考勤", "请假", "报销", "加班", "薪资"). Consistent terms across all files — record chosen terms in the locale files and reuse them.
- `AppError`/`apiErrorMessages` rule: `getErrorMessage` output goes through the `errors:api.*` map; unmapped messages fall back to `errors:api.unexpected` and `console.warn` the raw text.
- UI expansion: if a translated string overflows (sidebar, buttons, table headers, modal footers), fix the layout (wrap, `min-w-0`/`truncate`, wider column, stacked buttons) — never shorten the translation unnaturally.

- [ ] **Step 3: `apiErrorMessages.ts`**

```ts
// Backend `error` strings → errors:api.* keys. Exact-match first, then
// `includes` patterns. Anything unmapped falls back to errors:api.unexpected.
const EXACT: Record<string, string> = {
  'Invalid email or password': 'errors:api.invalidCredentials',
  // …seed with messages found in backend/src/core/error.rs + handlers…
};
const PATTERNS: Array<[RegExp, string]> = [
  [/rate.?limit|too many/i, 'errors:api.rateLimited'],
];
export function apiErrorKey(message: string): string | null {
  return EXACT[message] ?? PATTERNS.find(([re]) => re.test(message))?.[1] ?? null;
}
```
